# Notes for Claude

Read AGENTS.md first; it applies to every session.

## Documentation

The documentation is in `docs/`. Read the pages that touch the change before starting:
`CALCULATION_RULES.md` (rule IDs C01–C22) for anything that changes amounts, `ARCHITECTURE.md`
for how the pieces fit, `DECISIONS.md` for scope decisions, `STATUS.md` for what is done and
what is still open. `GLOSSARY.md` defines the domain terms; use its English terms in code.

## Reference implementations

Tax rules follow the sources linked in `docs/CALCULATION_RULES.md` (§ 9 EStG, R 9.7 LStR, BMF
letters); rate data lives in `data/*.csv` and is seeded, never hard-coded in `internal/calc`.

## Layout

- `internal/calc`: the only place for calculation rules. Pure functions, every result line carries
  a rule ID. Tests: `calc_test.go` (A01–A14) and `fixtures_test.go` (F01–F03).
- `internal/app`: persistence, ownership checks, audit, receipts, claims and submission.
- `internal/api`: Huma operations; the OpenAPI document is generated from them.
- `internal/export`: Typst template and ZIP; `internal/rates`: CSV validation and seeding.
- `web/`: React SPA. `web/src/api/gen` is generated by Hey API; never edit it.

## With every change

Update what the change affects, in the same pull request, and only that:

- the tests for what changed (Go table tests for rules, `internal/api` tests for auth/ownership,
  Playwright in `web/e2e` for user flows);
- after API changes: `mise run gen` (OpenAPI + client), commit both;
- new UI text in `web/messages/de.json` and `en.json`;
- `docs/STATUS.md` when a scenario's state changes, `docs/DECISIONS.md` for material assumptions.

## Checks

Green before every push, then check CI:

```sh
mise run check
SPESEN_BIN=$PWD/bin/spesen pnpm --dir web e2e   # after mise run build
```

## Pull requests

Standard procedure (owner decision): after pushing, open a ready-for-review pull request (drafts
do not run CI), watch CI until it is green, fix failures on the branch, then merge it yourself
(squash) and report the result. Ask first only when a change alters scope or financial results.

- Commit messages and pull request titles follow Conventional Commits (`feat:`, `fix:`,
  `docs:`, `test:`, `refactor:`, `chore:`, `ci:`, `build:`; optional scope such as
  `feat(calc):`). The squash commit uses the pull request title.
- One feature per pull request; it carries only its own commits.
- Before every push check whether the branch's pull request is still open. If it is merged, start
  again from the current `origin/main` and open a **new** pull request.

## Working rules

- Commands as root (`sudo`) are run by the user; don't work around that.
- Code, comments, docs, commits and pull requests in English; the app's interface in German and English.
- Money is integer cents (`money.Cents`); never use floats for amounts in Go.

## Code style

Technology choices follow the techstack-starter skill; deviations and why: Go backend with Huma
and Hey API instead of TanStack Start (small image, see DECISIONS.md); pnpm 12 (lockfile);
Hey API runs with TypeScript 6 in `web/tools/codegen` because TypeScript 7.0 has no compiler API.

Clean Code, written functionally: clear names, small functions that do one thing, dependencies
passed in, no duplication or dead code, comments that say why. Errors as values. A file does one
thing: split it past ~400 lines, a function past ~80. A refactor changes no behaviour.
